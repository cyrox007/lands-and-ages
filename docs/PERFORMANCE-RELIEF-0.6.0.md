# Производительность большого рельефа — исправление предпросмотра 0.6.0

## Обнаруженные проблемы

- Цикл UI перерисовывал неподвижный природный полигон каждый кадр, хотя климат и геометрия не менялись.
- Кеш содержал 16 чанков. Если было видно больше, последовательное вытеснение порождало повторную генерацию почти всех видимых чанков на каждом проходе.
- Каждый чанк хранил растр полного разрешения и содержал вертикальный запас по абсолютному перепаду высот всего мира, а не по перепаду конкретного чанка.
- Линии горизонталей рисовались даже при отдалённом масштабе, когда они малоразличимы.

## Изменения

- Перерисовка природного полигона выполняется только при повороте/сдвиге камеры, изменении масштаба, сезона и изменении размера окна. Сама экономическая игра продолжает обновляться по прежним правилам.
- Видимые чанки защищены от удаления до окончания кадра. Размер кеша адаптируется к числу видимых чанков, оставляя небольшой резерв.
- Разрешение текстур зависит от масштаба, без отрисовки лишних пикселей при отдалении.
- Вертикальный размер Canvas каждого чанка рассчитывается по локальным минимальной и максимальной высоте.
- Горизонтали рисуются только при достаточном приближении.
- В отладке доступны reliefDrawCount и статистика reliefDrawStats: число видимых, вновь сгенерированных и закешированных чанков, масштаб растра, ориентировочный объём RGBA-текстур.

## Критерии

- Неподвижный природный мир не пересоздаёт кадры; переключение сезона и перемещение камеры требуют нового кадра.
- Повторный drawVisible с той же камерой при числе видимых чанков больше 16 не генерирует ни одного чанка.
- npm run check, автономная сборка и Chromium smoke не имеют регрессий.

**Ограничения:** это исправление регрессии предпросмотра Canvas 2D, а не гарантия производительности полноценной стратегии. При движении камеры новые чанки пока генерируются синхронно. Нужны измерения кадрового времени и памяти на ПК/Android, а затем сравнительный прототип GPU-рендеринга (WebGL) либо специализированного движка (Godot).
