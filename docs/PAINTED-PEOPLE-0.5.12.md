# 0.5.12 — детализированные жители и рабочие

## Игровые ассеты

`assets/characters/painted-people.webp` — один оптимизированный прозрачный WebP-атлас, 1056×144, **11 ячеек по 96×144 пикселя**.

Порядок ячеек:

| Номер | Образ |
| --- | --- |
| 0 | Мужчина в зелёной тунике |
| 1 | Мужчина в коричневом жилете |
| 2 | Женщина в фиолетовом платье |
| 3 | Молодой поселенец в синем |
| 4 | Пожилой мужчина |
| 5 | Пожилая женщина |
| 6 | Носильщик с мешком |
| 7 | Строитель с молотком |
| 8 | Лесоруб с топором |
| 9 | Каменотёс с молотком |
| 10 | Земледелец с граблями |

Материал подготовлен из двух утверждённых изображений этой беседы. Исходники — детализированные концепт-листы 1448×1086; атлас уменьшен под экранные размеры и оптимизирован для мобильного браузера.

## Подключение

- В режиме поселения свободные жители перед складом отрисовываются **из этих изображений**, шесть разных типов чередуются без привязки внешности к профессии. Количество людей по-прежнему равно свободному населению (не более семи фигур возле центра).
- Рабочие 4 профессий (строитель, лесоруб, каменотёс, земледелец) используют детализированный образ **в покое**; при ходьбе и работе остаются существующие покадровые 4×8 анимации.
- Носильщик сохраняет прежнюю анимацию и отдельную отрисовку фактически переносимого ресурса. В рисунке носильщика мешок уже нарисован; использовать его как движущийся спрайт нельзя, поскольку возникнет ложный или дублирующийся груз.
- В карточке профессии показывается детализированный портрет из нового атласа.
- При ошибке загрузки WebP остаётся прежний векторный спрайт. Текущие маршруты, экономическая симуляция, сохранения и лимиты населения не изменены.
- Обычная страница загружает WebP-файл из каталога `assets`. Автономный `play.html` встраивает тот же атлас как data URI.

## Анимационные ограничения

Рисунки представляют **один ракурс и одну позу** каждого персонажа. Техническая анимация ожидания — небольшое плавное покачивание вокруг неподвижной точки опоры. Отражение исходного портрета и искусственное движение по карте не выдается за полноценные четыре ракурса ходьбы.

Для полностью детализированного движения понадобятся согласованные ракурсы и самостоятельные кадры ходьбы, работы и переноски. Пока сохраняются существующие корректные циклы, чтобы у жителей не было «скольжения».

## Контроль качества

- Node.js проверяет логику, автономную сборку и старые игровые механики.
- Chromium проверяет загрузку атласа, размеры 1056×144, отрисовку спрайтов в Canvas на ПК и мобильном экране.
- Внешний вид на реальном Android, читаемость на разных масштабах и качество краёв требуют ручной художественной приёмки.
