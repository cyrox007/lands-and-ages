# Проверки CI в активной разработке

Основная ветка разработки — `develop`. В рамках этапа 10 проверяем в PR
только затронутые системы, а полную старую регрессию запускаем перед релизом
или при изменениях общей архитектуры.

| Проверка | Автоматический запуск | Ручной запуск |
| --- | --- | --- |
| `godot-nature.yml` | Изменение природы, общей физики или её тестов | Да |
| `godot-coast-smoke.yml` | Изменение берегов, воды, береговых тестов | Не требуется |
| `check.yml` | Изменение браузерной стратегии 0.4 | Да |
| `godot-pilot.yml` | Нет, полный старый набор | Да |
| `godot-world-stress.yml` | Нет, многолетний прогон | Да |
| `world-visual-qa.yml` | Нет, программная графическая приёмка | Да |
| `world-android-debug.yml` | Нет, Android APK с шаблонами | Да |

Для ручного запуска: GitHub → Actions → нужный workflow → Run workflow,
ветка `develop` или ветка проверяемого PR.

Перед выпуском сборки **обязательно** запускаются Godot GPU world pilot,
многолетний прогон, визуальная QA и Android APK; для изменений веб-игры —
проверки стратегии 0.4. Техническая зелёная проверка Godot не равнозначна
измерению FPS на реальном смартфоне.

При изменении общего файла `world.gd`, `world_save.gd`,
`world_day_runner.gd` либо `climate.gd` запускается smoke этапа 10.
При масштабной реконструкции этих систем вручную проверяем и полный набор.

Так мы не тратим несколько параллельных CI-машин на повторение
исторических тестов после каждого изменения модели деревьев.
