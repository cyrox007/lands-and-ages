# Версия 0.5.13 — движущиеся детализированные жители

## Реализация

- Новый `painted-motion.js` использует утверждённый WebP-атлас `assets/characters/painted-people.webp` и не меняет правила симуляции.
- Состояния `idle`, `walk`, `work`, `carry` получают разные рисунки **из одной исходной детализированной фигуры** через поворот/смещение корпуса и ног, в ритме уже вычисленных игровых кадров.
- Стадия ходьбы берётся из пройденной дистанции. Пятки персонажей остаются привязаны к координатам движка.
- Все пять профессий используют детализированную графику не только в покое, но и в движении/работе.
- У портера не используется художественное изображение с уже нарисованным мешком. Его игровое тело рисуется в одежде гражданского из того же утверждённого набора; настоящий груз отображается только отдельным слоем из `carrying`. Портрет портера остаётся прежним.
- Гражданские у главного здания также используют новый рендер покоя.
- При недоступности утверждённого атласа остаются прежние покадровые векторные атласы/условные фигуры.
- Генератор включён в автономный `play.html`; состояние партии/сохранения не меняются.

## Приёмка

- Unit-тесты: контракт состояний, направления, покадровое движение, отрисовка через Canvas, отсутствие лишнего груза на изображении портера.
- Browser smoke: все четыре состояния действительно изменяют пиксели художественного изображения. Проверяется и мобильный viewport.
- Работу на физическом Android устройстве и производительность длинной партии нужно подтвердить отдельно.

## Оставшаяся художественная работа

**Важно:** это композиционная анимация из одного утверждённого ракурса, а не четыре вручную нарисованных полноценных направления 4×8 на каждое действие. Отражение изображения для левосторонних направлений — промежуточная мера. Для истинной смены ракурса и отдельно нарисованных рук/инструментов потребуется новый комплект художественных кадров. Нельзя выдавать процедурную анимацию одного изображения за уже готовую полную ручную покадровую рисовку.
