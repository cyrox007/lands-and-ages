# Этап 8.7 — воспроизводимый маршрут производительности камеры

Этап 8.7 закрепляет **одинаковый сценарий измерения** после оптимизаций 8.3–8.6. Генерация мира, законы физики и структура сохранений не изменяются.

## Фиксированный маршрут

`godot/scripts/world_benchmark_route.gd` определяет версию маршрута 1: **370 кадров в 9 фазах**. Исходный мир — 256×192 с прежним seed 1729; координаты заданы долями ширины/высоты карты, а масштабы явно зафиксированы.

1. Холодная прорисовка центральной области.
2. Приближение к поверхности.
3. Короткий проход камеры.
4. Возвращение для проверки повторного использования мешей.
5. Длинная панорама к одному краю карты.
6. Пересечение карты в обратном направлении.
7. Отдаление до общего обзора.
8. Обратное приближение.
9. Неподвижный участок для завершения очереди.

**Каждая фаза имеет фиксированное количество кадров.** Результат не зависит от реального времени ожидания между шагами, числа FPS или случайных событий. На движущейся камере используется существующий планировщик GPU-чанков и реальная сцена `world.gd`.

## Что записывается

Запускаемый тест `godot/tests/world_camera_benchmark.gd` сохраняет JSON со стабильными полями (`schema_version=1`, `route_version=1`):

- Среднее не подменяет хвосты задержек: фиксируются **p50/p95/p99 и максимальный интервал кадра** в миллисекундах.
- По каждой фазе — число кадров, p50/p95/максимум времени CPU-очереди генерации мешей, число построенных чанков, попадания/вытеснения из кеша, число отброшенных задач.
- Максимальная длина очереди, число видимых чанков, пик оценочных байтов вершин/индексов в кеше и пик **статической памяти Godot**.
- Время начальной инициализации мира, конфигурация карты, версия Godot, режим запуска, итоговый размер очереди и проверка неизменности физического снимка.

Важное различие: время CPU-очереди измеряется существующим `_last_chunk_build_us`, **не** полным временем GPU. Статическая память движка **не равна** общей RAM, а бюджет вершин кеша **не равен** выделенной VRAM.

## Запуск

Из корня репозитория на ПК с Godot 4.7.2:

```sh
godot --headless --path godot --script res://tests/world_camera_benchmark.gd \
  -- --report=world-camera-8-7.json
```

Для сравнения на ПК с графическим окном уберите `--headless`. Если `--report` не задан, файл пишется в `user://world-camera-8-7.json`. В отчёте отмечен `headless`, поэтому автоматические результаты нельзя путать с аппаратным измерением.

В GitHub Actions JSON автоматически загружается как артефакт **`world-camera-8-7`** каждого запуска рабочего процесса Godot. CI требует успешного прохождения маршрута, правильной схемы данных, ограничений кеша и сохранности физики, **но не устанавливает произвольный порог FPS** на виртуальном runner.

Сравнивать имеет смысл прогоны на **одном устройстве и с одинаковыми настройками**: версия Godot, размер окна, режим рендера, ограничение FPS, фоновая нагрузка. Для Android-приёмки потребуется запуск того же сценария в реальной сборке и отдельные показатели батареи/температуры — это часть 8.8.

## Критерий завершения

- Все девять фаз воспроизводимы и дают валидный JSON.
- В отчёт попадают фактические построения, использование кеша, задержки кадров и память.
- Превышение лимитов кеша либо изменение физического снимка вызывает ошибку.
- Headless CI хранит отчёт для последующего сравнения, но не объявляет его показателем реального FPS ПК/Android.
